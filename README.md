# Pansol: find the right plant for your soil

Pansol is a full-stack web app that recommends plants by soil type and category,
with plant care guides behind a login.

**Stack:** React 18 + Vite · Node.js 22 + Express · SQLite (`node:sqlite`) ·
Docker · Terraform · AWS (EC2, ECR, VPC, IAM, SSM, CloudWatch, SNS) · GitHub Actions

```
 Developer ──push──▶ GitHub ──▶ GitHub Actions
                                  ├─ CI (PRs): tests · client build · Docker build · Trivy scan
                                  │            terraform fmt/validate · shellcheck
                                  └─ CD (main): tests ─▶ docker build ─▶ Amazon ECR
                                        │  (OIDC role, no stored AWS keys)
                                        ▼
                         AWS SSM send-command ─▶ EC2 (Amazon Linux 2023, admin via SSM only, no SSH)
                                                  └─ Docker Compose: Pansol container :80 → :4000
                                                       └─ SQLite on encrypted EBS volume
                                        ▼
                                   smoke test /api/health
 CloudWatch Logs (JSON request logs) ─▶ metric filter + alarms (CPU, status check, 5xx errors) ─▶ SNS email
 All infrastructure is defined in terraform/
```

## Run locally

```bash
npm install
npm run dev          # API on :4000, React dev server on :5173
npm test             # API tests (Node's built-in test runner)
```

Run the production container locally:

```bash
docker compose up --build    # http://localhost:8080
```

## Repository layout

| Path | Purpose |
|---|---|
| `client/` | React front end (Vite) |
| `server/` | Express API. `app.js` builds the app, `index.js` starts it with graceful shutdown |
| `server/sessionStore.js` | SQLite-backed session store, so logins survive restarts and redeploys |
| `server/test/` | API tests: health, soils, filtering, search, auth-gated details, sessions |
| `Dockerfile` | Multi-stage build: client build → prod-only server deps → slim non-root runtime with HEALTHCHECK |
| `docker-compose.yml` | Run the production image locally |
| `deploy/` | Production compose file and the deploy script that runs on EC2 |
| `terraform/` | All AWS infrastructure as code |
| `.github/workflows/` | `ci.yml` (pull requests) and `deploy.yml` (main → AWS) |
| `scripts/healthcheck.sh` | Post-deploy smoke test with retries |

## Deploy to AWS

### 1. Prerequisites
- An AWS account with an **AWS Budget alert** (for example $5) set up first.
- AWS CLI configured (`aws configure`) and Terraform ≥ 1.6 (`brew install terraform`).

### 2. Create the infrastructure

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # set github_repo, aws_region, alert_email
terraform init
terraform plan
terraform apply
terraform output
```

Confirm the SNS subscription email from AWS so alarm emails arrive.
If `apply` says the GitHub OIDC provider already exists, set
`create_github_oidc_provider = false` in `terraform.tfvars`.

### 3. Connect GitHub Actions

GitHub → *Settings → Secrets and variables → Actions → Variables* (values from `terraform output`):

| Variable | Value |
|---|---|
| `AWS_REGION` | e.g. `us-east-1` |
| `AWS_ROLE_ARN` | `github_deploy_role_arn` |
| `ECR_REPOSITORY` | `pansol` |
| `EC2_INSTANCE_ID` | `ec2_instance_id` |
| `APP_URL` | `app_url` (ends with `/`) |

Create an environment named `production` (*Settings → Environments*), then push to
`main`. The **Build and Deploy** workflow tests, builds, pushes, deploys and smoke-tests.

### 4. Check monitoring
- Logs: CloudWatch → Log groups → `/pansol/app` (one JSON line per request).
- Test the CPU alarm: `aws ssm start-session --target <instance-id>`, then
  `sudo dnf install -y stress-ng && stress-ng --cpu 2 --timeout 900s`. An email should arrive within about 10 minutes.

### Rollback
Re-deploy any earlier image by commit SHA:
```bash
aws ssm send-command --instance-ids <id> --document-name AWS-RunShellScript \
  --parameters 'commands=["/opt/pansol/deploy.sh <older-commit-sha>"]'
```

### Tear down
```bash
cd terraform && terraform destroy
```

## Design decisions

- **OIDC instead of AWS access keys:** GitHub gets short-lived credentials, and the role only trusts `main` of this repo.
- **SSM instead of SSH:** no port 22, no key pairs, and every deploy command is logged in AWS.
- **Least-privilege IAM:** the instance can pull one ECR repo, write one log group and read one secret.
- **Secrets:** the session secret is generated by Terraform and stored as an SSM SecureString, never in Git.
- **Health checks at three levels:** Docker `HEALTHCHECK`, the deploy script waits for healthy, and the pipeline smoke-tests `/api/health` (which also queries the database).
- **Hardening:** non-root container, IMDSv2 required, encrypted EBS, ECR scan-on-push, Trivy scan in CI.
